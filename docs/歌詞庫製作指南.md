# 歌詞庫製作指南

網頁不用即時 AI，而是從**事先寫好的歌詞庫**依「情境＋抱怨」挑一首最適合的歌。歌詞庫越大、tags 越完整，使用者越容易覺得「它懂我」。

- 歌詞庫：[`js/lyric-library.js`](../js/lyric-library.js)
- 配對規則：[`js/lyrics.js`](../js/lyrics.js)
- 試配對：打開 `tools/lyrics-demo.html`（要用 Live Server 或本機伺服器）

## 配對怎麼運作

1. 使用者選了情境 → 只在那個情境的歌裡挑；選「其他鳥事」或沒選 → 整個歌詞庫都能挑。
2. 抱怨裡出現某首歌的 `tags` 就加分，詞越長分數越高。
3. 分數最高的歌裡隨機挑一首；都沒對到就隨機。
4. 專輯頁會顯示曲名，例如「主打歌〈週末被取代〉」。

所以 **tags 決定配對準不準**：一首歌在講「離職交接」，就要把「離職、交接、走了、爛攤子、接手」這些使用者可能會打的字都列進去。

## 一首歌的格式

```js
{
  id: "rush-05",            // 不可重複：情境id-編號
  scenario: "rush",         // guess / revise / rush / firefight / leave / other
  title: "曲名",
  tags: ["關鍵字1", "關鍵字2", "同義詞"],
  lines: [                  // 剛好 8 句
    "第一句 用空白標換氣",
    // ...
  ],
},
```

## 用 AI 批次產生（免費的 AI 聊天網頁就可以）

把下面整段貼給 ChatGPT、Claude 或 Gemini，把 `【】` 換掉：

```
你是「職場功德所」的駐殿小師父：戴墨鏡、會饒舌的 Q 版小和尚。
請替職場情境「【臨時加單：主管說很簡單，五分鐘就好】」寫 【5】 首饒舌歌詞，
每首聚焦不同的小情境（例如：下班前丟來、群組標記、週末被佔用⋯⋯）。

規則：
- 台灣口語繁體中文，可以夾一點職場英文（KPI、meeting、deadline）。
- 每首剛好 8 句，每句 8～12 個字，用一個空白標出換氣的位置。
- 每首全部押同一個韻，韻腳放在句尾。
- 可以混佛門用語（阿彌陀佛、業障、功德、善哉）製造反差。
- 酸的是情境，不是人：不針對身分、外貌、性別、年齡、族群、疾病、身心障礙或死亡；不罵髒話；不點名真實公司或人。
- 功德不等於忍耐：不要勸人吞忍、加班或犧牲。最後兩句轉成守住界線或放下的祝福。

每首另外給：
- title：4～8 字的曲名
- tags：8～12 個使用者抱怨時可能會打的詞（含同義詞、口語寫法）

請用這個 JavaScript 格式輸出，id 從 【rush-05】 開始編：
{ id: "", scenario: "【rush】", title: "", tags: [], lines: [] },
```

## 放進歌詞庫前要檢查

- [ ] 每首剛好 8 句，每句字數差不多（念起來節奏才穩）
- [ ] 真的有押韻，大聲念一遍
- [ ] 沒有破音字或容易念錯的詞（AI 語音常念錯「重、還、行、長」）
- [ ] 沒有越界：不酸人、不歧視、不勸人吞忍
- [ ] tags 夠多：想像使用者會怎麼打字，同義詞都列進去
- [ ] `id` 沒有重複
- [ ] 在 `tools/lyrics-demo.html` 打幾句抱怨，確認會挑到這首

## 目標

每個情境 15～20 首，總共 100 首左右。目前共 50 首，每個情境 8～9 首。

> 想要配預錄的人聲或 AI 唱的版本時，音檔可以用歌的 `id` 命名（例如 `assets/music/album/rush-02.mp3`），之後再改程式讓它依 id 播放。
